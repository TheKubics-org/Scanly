1. Introduction & Core Philosophy

Welcome to Scanly ("the App"), a document scanning, optical character recognition (OCR), and PDF creation tool developed by TheKubics ("we", "us", or "our").

We hold a simple, uncompromising privacy principle: your documents belong solely to you. Scanly is architected from the ground up as an offline-first utility:

  • No Developer Tracking: We do not collect, transmit, store, sell, or monetize your personal information, scanned documents, images, or metadata on any developer-owned or third-party servers.
  • No Third-Party Advertising: The application contains zero advertising SDKs, ad networks, or commercial trackers.
  • No Third-Party Analytics: We do not embed analytics tracking platforms (such as Google Analytics, Firebase Analytics, Mixpanel, or Facebook SDK).
  • Decentralized & Private: All processing, edge contour detection, and PDF generation happen locally on your device.

2. Permissions and How They Are Used

Scanly requests the minimum Android system permissions necessary to operate as a document scanner. Each permission is used strictly on-device:

Permission Purpose & Scope
android.permission.CAMERA Used solely to capture document photographs and provide live viewfinder edge detection. Camera frames are processed in volatile memory on your device and are never streamed or uploaded to developer servers.
READ_MEDIA_IMAGES / READ_EXTERNAL_STORAGE Used strictly when you manually choose to import existing photographs from your device gallery into Scanly for document scanning.
WRITE_EXTERNAL_STORAGE (Legacy) Used exclusively on Android 9 and lower to write exported PDF documents and images to your public Download or Documents folder upon user request.
android.permission.INTERNET Used exclusively for user-configured, decentralized cloud storage sync (e.g. Telegram Bot API cloud backup, Google Drive). If you do not configure cloud backup, no internet connections are ever established by the application.
USE_BIOMETRIC Used to protect private documents behind device biometric authentication (Fingerprint / Face Unlock / Screen PIN) via Android's native BiometricPrompt. Biometric data is evaluated strictly within Android's hardware Trusted Execution Environment (TEE) and is never accessible to the app.
POST_NOTIFICATIONS Used on Android 13+ solely to display local foreground progress notifications while exporting multi-page PDFs or running user-requested cloud backups.

3. On-Device Machine Learning & Computer Vision

Document quad edge contour detection and Optical Character Recognition (OCR) are powered by Google ML Kit's on-device machine learning models. All visual analysis and text extraction execute 100% locally on your device's hardware. No scanned images or text are transmitted to Google cloud servers for machine learning inference.

4. User-Controlled Cloud Storage (BYOS — Bring Your Own Storage)

Scanly provides an optional cloud backup engine built on a Bring Your Own Storage (BYOS) model:

  • Direct User-to-Provider Communication: If you configure cloud storage (such as Telegram Cloud storage), Scanly communicates directly with the designated API endpoint using your own credentials (e.g., your private Telegram Bot token and chat ID).
  • Zero Intermediary Relays: TheKubics does not operate any intermediate proxy servers, relay databases, or monitoring systems. Transmissions occur directly between your phone and your private storage endpoint over TLS/HTTPS encryption.
  • Hardware Keystore Vault: Cloud credentials and bot tokens are secured in hardware-backed encrypted storage (EncryptedSharedPreferences backed by Android Keystore using AES-256-GCM encryption).

5. Data Storage, Retention, and Deletion

  • App Sandboxing: Scanned files, thumbnail caches, and SQLite database records reside in Android's sandboxed internal storage (/data/data/com.thekubics.scanly/).
  • Instant Permanent Deletion: Deleting a document or purging the trash within the app immediately and permanently wipes the associated files from device storage.
  • Clean Uninstall: Uninstalling Scanly permanently removes all internal databases, cache files, and encrypted credentials from your phone.

6. This Website

This policy so far has described the Android App. This section covers scanly.thekubics.space, which is a static site. It is deliberately blunt about what happens when you load a page here:

  • No cookies. The Site sets none, so there is nothing to consent to and no cookie banner to click past. We consider a consent dialog on a cookie-free site to be a dark pattern, so there is deliberately not one.
  • No analytics, no advertising, no tracking pixels, no fingerprinting, no third-party embeds. There is no JavaScript from any other origin on any page.
  • One piece of local storage. Your light/dark/system theme choice is written to your browser's localStorage under the key scanly-theme. It never leaves your device, is not transmitted to us, and clearing site data removes it. It is not a cookie and is not used to identify you.
  • Fonts are self-hosted. Typefaces are served from this origin rather than from Google Fonts, so loading a page here discloses no IP address or referrer to Google. This is a deliberate privacy choice.
  • No forms, no accounts, no contact-through-the-site form. Because the Site collects nothing, there is no data for you to consent to sharing, and therefore no consent checkbox to tick.
  • Server logs. Our host (GitHub Pages) may keep standard request logs such as IP address, timestamp and requested path, for security and abuse prevention. We do not use them for marketing or profiling, we do not combine them with any other data, and we do not control how long the host retains them.

11. Security Architecture

The App incorporates proactive security defenses:

  • Hardware-Backed Cryptography: Master keys generated within the device's hardware security module (Secure Element / TEE).
  • Screen Protection: Optional FLAG_SECURE window protection prevents unauthorized screenshots and app switcher previews.
  • Scoped Storage Isolation: Strict compliance with modern Android scoped storage and data backup extraction rules.
